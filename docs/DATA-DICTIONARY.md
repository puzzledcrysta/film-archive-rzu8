# 胶片修复拼接字段定义

| 字段 | 类型 | 定义 |
|---|---|---|
| 扫描段 | 字符串 | 保留前导零，旧名为业务编号 |
| 修订号 | 整数 | 正整数，兼容版本列。最高修订的业务值一致时保留首次原始行 |
| 提交时间 | RFC 3339 时间 | 必须含偏移量，统一为 UTC，版本裁决以修订号为准 |
| 起片帧 | 业务文本 | 必填，按业务段解析 |
| 止片帧 | 业务文本 | 必填，按业务段解析 |
| 扫描帧段 | 业务文本 | 必填，按业务段解析 |
| 判废帧段 | 业务文本 | 必填，按业务段解析 |
| 原始备注 | 字符串 | 可空，可内含换行 |
| 外部记录值(帧) | 十进制数 | 参照值。真实零值与找不到键分别表示 |

帧段两端均包含。越过目标起止的原始扫描会被裁切，判废帧须在有效扫描里才扣除。

空字符串、`N/A`、`-`、`NULL`、`未知` 均拦在必填的主键、修订号和提交时间。业务字段的显式哨兵同样拒绝；`无` 可以表示空集合，按具体业务字段解释。
逐行记录保留物理起始行号。JSON 的计量值为十进制字符串。

## 补发折叠

同一扫描段按修订号升序折叠，裁决只认最高修订的字段签名，同修订精确重复只保留首行：

- 业务字段**留空**表示本次补发未改该项，沿用上一版累积值；不会被当作清空。
- 业务字段写 **`无`** 表示明确清空为空集合（例如清空判废帧段后，原扣除帧恢复可用）。
- 折叠后的最终状态必须四项业务字段全部闭合，否则整卷以 `PATCH_INCOMPLETE` 隔离；中间修订允许暂时缺项，由更高修订补齐。
- 每个采信结果带 `revisions` 轨迹，逐修订记录实际变更字段与该时点的最终可用帧段 `available_text`。
- 最终可用帧段 = 目标范围内的扫描并集减去判废并集（含尾区间），同时给出结构化 `available` 与文本 `available_text`。

## 流水线记录

运行清单保存来源和外部账的 SHA-256、规则版本、耗时、计算参数和创建时刻。
影子版本与重复行保留原始字段。复核按版本追加，旧版本提交返回 409。

导入原文件时指纹取源字节，编辑预览后以提交的 UTF-8 文本计算。
